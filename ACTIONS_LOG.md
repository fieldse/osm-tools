# Actions Log

- 2026-06-02 change - **phase 1 foundation**: set up the CLI skeleton, shared error types, and the rule that maps failures to exit codes
- 2026-06-02 change - **phase 2 config & auth**: added the `osm config` command to save an API key and the logic that picks a token from flag, env var, or saved file
- 2026-06-02 change - **phase 3 api client**: built the layer that talks to the OSM service, keeps requests under the rate limit, and sorts out the different ways a request can fail
- 2026-06-02 change - **phase 4 check command**: added `osm check`, which guesses whether you're asking about a package, domain, IP, or image, looks it up, and prints the result
- 2026-06-02 change - **phase 5 cache**: added a local 24-hour memory of past lookups so repeated scans skip re-asking the API; not yet used by any command
- 2026-06-02 change - **phase 6 sweep**: added `osm sweep`, which reads a dependency file, checks every package at once, prints the results, and can fail a CI build if anything's malicious
- 2026-06-02 change - **phase 7 latest**: added `osm latest`, which pulls the most recently flagged threats for chosen ecosystems (or all) and prints them as JSON
- 2026-06-02 change - **structure cleanup**: moved type-guessing and the list of known ecosystems out of the command layer into their own focused pieces, and removed a duplicated helper, after a structural review
- 2026-06-02 change - **phase 8 hardening**: added end-to-end tests that run the real program, a timing test proving request pacing works, refreshed the docs, and confirmed a clean build before release
- 2026-06-02 change - **check command debug**: added a `--debug` flag to `check` that prints the API request and response status (never the token)
- 2026-06-02 change - **dropped .env**: removed the unused .env convention the program never read; documented the export and `osm config` paths instead
- 2026-06-02 change - **build script**: added build.sh that compiles the tool into ./bin
- 2026-06-02 bug - **wrong API base path and response shapes**: live calls 404'd because the base URL and the check/latest response field layouts were modeled from notes, not the real API; corrected against the live docs and verified working
- 2026-07-12 change - **submit command**: added `osm submit`, the first command that files a threat report to OSM, with three ways to compose one (a template file, a JSON file, or guided prompts) and a preview-then-confirm guardrail so nothing is sent until you approve it; live malware links in the writeup are automatically neutralized before sending
- 2026-07-16 change - **submit wizard usability**: the interactive prompts were bare API field names — no vocabulary, no defaults, no sign of what was required; every prompt now states required/optional, offers its accepted values or an example, and defaults report_type to package and registry to npm (packages only). A bad report_type or blank required field is re-prompted on the spot instead of failing at the end, the long description/payload/evidence prompts show a worked example, and pasted "- " evidence bullets are stripped
- 2026-07-16 bug - **Ctrl-C did nothing at a prompt**: main catches SIGINT to cancel in-flight requests, which also suppresses Go's default kill — but the wizard and confirm prompt blocked on a raw stdin read that never watched the context, so Ctrl-C echoed "^C" and the prompts carried on forever. Prompt reads now go through one cancellable line reader; an interrupt before send reports the same clean "aborted" as declining, and an interrupt during the POST says the report may or may not have been filed rather than implying nothing was sent
- 2026-07-16 bug - **two readers racing on stdin**: the wizard and the confirm prompt each built their own stdin scanner, so an abandoned wizard goroutine could swallow the confirm answer and silently drop a "y". Both now share one reader per run
- 2026-07-16 change - **submit wizard prompt layout**: the field name, hint/enum, and default were on one line, which overflowed the terminal on the longer prompts; each prompt now breaks across lines — name/required/default first, options or example on an indented line, answer after a "> " marker — and the default is named explicitly as "[default: X]" so it's clear which piped option Enter selects
- 2026-07-16 change - **submit wizard defaults on the input line**: moved the default off the header ("[default: X]") and onto the "> " prompt line so it's visible right where you type and Enter accepts it; first_seen now defaults to today and dates use the shorter YYYY-MM-DD form (validator broadened to accept date-only alongside full RFC 3339). Added a clock seam on submitOptions so the today() default is testable
